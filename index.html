      How Intent Sentinel works

      A cross-chain swap passes through several systems. When it stalls, it's hard to tell whose move it is. Intent Sentinel reads the public record and tells you.

      Four stepsReading the pictureThree real casesWho it can nameWhy you can trust itWhat it can't tell youYour privacyWords used here

      Four steps

      1. You paste one IDA transaction hash, an explorer link, an Omni transfer ID or a deposit address.
      2. It reads public recordsYour browser asks the chains and bridges directly. Cryppit runs no server for this.
      3. It labels every factEach step is marked proven, reported, inferred or not visible.
      4. Fixed rules decide18 written rules name the next move. If proof is missing, it says so instead of guessing.

      How to read the picture

      1. TickA chain record proves this stop
      3. GlowThe proof ends here
      5. DashedNot reached, or not seen

      A beam then points from the last stop to whoever can act next. If nobody needs to act, it points to "Nobody". Each stop also carries one of four labels:

      ProvenA chain shows itA transaction, receipt or contract says so.
      ReportedA provider said soWorth knowing, but it isn't proof.
      InferredThe facts line upNothing proves the link yet.
      Not visibleConfidentialA private step only its owner can read.

      Three real cases

      0.02 ETH, fee 0The transfer started on NEAR but never finished. Only an Omni relayer can run the next step, so the sender can't fix it alone.
      Solana transferThe Solana deposit is proven, but Omni's records don't show it. The bridge step is only inferred, and the label says so.
      5 BTC refundedThe deposit, the credit and the refund are all proven, and the amounts balance. Nobody needs to act.

      Who it can name

      YouSomething is waiting on your side.
      Your appThe wallet or site you swapped through.
      SolverThe party that fills the swap.
      NEAR IntentsThe system holding the balance.
      Omni relayerThe operator allowed to run a gated bridge step.
      AnyoneThe last step is open, so anyone can run it.
      NobodyThe case is finished.
      Someone elseA downstream provider, or nobody it can name yet.

      Why you can trust the answer

      Same evidence, same answerEach case gets an incident ID and a fingerprint. Anyone can rerun it and compare. A new chain event changes the fingerprint.
      A packet you can hand overDownload the evidence for a support ticket. It holds only proven chain evidence, and an edited packet fails verification.
      A daily pin on NEARA day's packets can be combined into one hash and pinned on NEAR, to show a record wasn't changed later. The tool is built, but no day has been pinned yet.

      What it can't tell you

      • It names who acts next, not who's to blame.
      • It can't move funds or make anyone act.
      • If a source can't be read, you get no answer rather than a guess.
      • A recorded case shows the chain as it stood when it was recorded.

      It never asks for a key. If someone offers to recover your funds by DM, it's a scam.

      Your privacy

      What you paste goes straight from your browser to public sources: chain endpoints, bridge records and public explorers. A deposit address also goes to 1Click, which is how the order is found. The page has no analytics, stores nothing in your browser and sends no referrer.

      Words used here

      IntentA request like "swap this for that", which others compete to fill.
      BridgeA system that moves value between chains.
      RelayerAn operator that carries a bridge step from one chain to another.

      FingerprintA short code that changes if the evidence changes.
